## 为什么要有这套标准

一份公开的初创公司研究，最大的失败不是「信息少」，而是「把公司的自我宣传当成事实」。
本目录的唯一竞争力是**可核查性**：读者应能顺着文中的来源，自己复现每一条结论。

## 收录标准

一篇研究要同时满足：

1. **多来源交叉验证**：关键事实（融资、估值、成立时间、主体归属）至少有 **2 个独立来源**，且不能都是同一家媒体的转载稿。
2. **区分事实与宣称**：公司官网/通稿给出的数据一律标注「官网宣称」，不得写进结论句当作已核实事实。
3. **写清「查不到」**：无公开融资记录、无团队信息、无员工口碑——**明确写出「查不到」比留白更有价值**，它本身就是风险信号。
4. **风险按严重度排序**：至少指出 1 个「最核心风险」，而不是罗列一堆并列的小毛病。
5. **给出可执行的核实动作**：结尾附「待核实清单」，让读者知道下一步该问什么、查什么。
6. **标注调研日期**：初创公司数据半年即过期，无日期的研究不予收录。

## 文件结构模板

按此顺序组织（可增不可乱）：

```markdown
# 公司名 英文名

> 调研日期：YYYY-MM-DD ｜ 结论速览：一段话说清「是什么 + 真不真 + 风险在哪 + 该怎么判断」。

## 公司基本面        ← 表格：全称/成立/规模/定位/客群/融资/资质
## 产品线            ← 有什么，卖给谁
## 技术背书与生态参与  ← 表格，必须带「可验证性」一列
## 风险分析          ← 按严重程度排序，第一条标「（最核心）」
## 竞品格局          ← 国内同赛道 / 降维打击方 / 海外对标
## 分场景判断        ← 什么情况下值得考虑，什么情况下不建议
## 待核实清单        ← checkbox 列表
## 参考来源          ← 全部外链，每条注明它支撑了上文哪个结论
```

## 证据分级

写作时心里给每条信息定级，并在措辞上体现出来：

| 级别 | 来源类型 | 允许措辞 |
|---|---|---|
| A 已核实 | 工商登记、许可证编号、SEC/港交所公告、代码仓库、招聘平台在册数据 | 直接陈述 |
| B 单一媒体 | 一家媒体的报道，无第二来源 | 「据报道」「×× 报道称」 |
| C 公司宣称 | 官网、通稿、发布会 PPT 的性能与规模数据 | 「官网宣称」「公司自述」 |
| D 无公开信息 | 查不到 | **写明「公开渠道无记录」**，并作为风险项计入 |

禁止：把 C 级写成 A 级；把 B 级重复引用当作多源验证；用「据悉」掩盖无来源。

## 结构化信息的固定来源

| 信息 | 优先来源 |
|---|---|
| 主体、股东、关联公司 | 企查查 / 天眼查（写明主体全称，注意沪/京/深多主体可能不同） |
| 融资与估值 | 官方公告 → 一线财经媒体 → 数据库，依次降级 |
| 技术成色 | GitHub 仓库活跃度、star、贡献者构成（比任何奖项都可靠） |
| 资质证照 | 工信部 / 主管部门公示名单（如 IDC 许可证编号可在发放名单中核对） |
| 团队与口碑 | 脉脉、看准、职友集；**「零评价」本身要写出来** |
| 在招岗位结构 | 猎聘 / BOSS，岗位构成能反推公司是重交付还是重研发 |

## 中立性要求

- **不写无依据的褒贬形容词**。「极具潜力」「碾压级」这类判断须紧跟证据，否则删。
- **区分「公司不好」与「公司不透明」**。前者是事实判断，后者是信息判断，结论应说明是哪一种。
- **奖项与榜单默认降权**。含付费/PR 成分的榜单只能作为辅证，须注明「参考即可」。
- **不软广**。与任何公司无商业合作；若调研对象是投稿方自己，须在文首声明利益相关。
- **允许否定结论**。「不建议投入时间」是可以写的，只要每条理由都能溯源。

## 更新与纠错

- 数据过期：重跑调研后更新文首「调研日期」，不删除旧结论，改为「截至 YYYY-MM」。
- 发现错误：直接提 PR 修正；无法当场核实的说法，降级为「存疑」而不是悄悄删掉。
- 补充案例：新增 A 级来源可以提升已有结论的证据等级，在 PR 描述里说明改判理由。
